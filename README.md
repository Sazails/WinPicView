# WinPicView

**WinPicView is a tiny, fast, fully offline image viewer for Windows 11, written in Rust. It opens a picture in about a tenth of a second, lets you zoom with the mouse wheel, drag to pan, and flip through the other images in the same folder with the arrow keys. No accounts, no cloud, no telemetry.**

> 🤖 **Generated by Claude.** This entire project (code, build script, icon, registry integration and this documentation) was written by [Claude](https://www.anthropic.com/claude), an AI model by Anthropic, running as a coding agent, for Windows 11. A human directed the work and reviewed the results.

- Single `.exe`, no installer, no runtime, no GPU requirement
- Per-user default-app registration for the common image formats (no admin rights)
- About 1,200 lines of Rust

## What it does

- **View** PNG, JPEG, WebP, GIF (first frame), BMP, TIFF, ICO, TGA, QOI, HDR, OpenEXR and PNM/PPM images
- **Zoom** with the mouse wheel (centred on the cursor), `+` / `-`, or double-click to toggle fit / 100%
- **Pan** by dragging with the mouse
- **Browse** the current folder with **Left / Right** (also PgUp/PgDn, Space/Backspace, mouse back/forward buttons), **Home / End** for first/last. Order matches Windows Explorer's natural sort (`img2` before `img10`)
- **Preload** the neighbouring images so the next picture appears instantly
- **Respect EXIF orientation**, and rotate the view with `R` / `Shift+R`
- **Fullscreen** (`F`, `F11`, `Enter`), dark title bar, high-DPI aware
- **Info panel** (`I`): file name, position in folder, pixel size, format, file size, zoom
- **Open** with `Ctrl+O` or by dragging a file onto the window
- **Copy** the image to the clipboard (`Ctrl+C`), **show in Explorer** (`Ctrl+E`), **delete to the Recycle Bin** (`Delete`)
- **Register as a default app** for image types: `winpicview.exe --install`

Press `H` or `F1` in the app for the full list of shortcuts.

## What it does not do

By design it is a viewer, not a photo manager.

- No accounts, sign-in, cloud sync, online storage or social features
- No telemetry, network access or update checks of any kind
- No library, albums, face/people grouping, indexing or search
- No editing, filters, cropping, or saving rotated files (rotation is view-only)
- No slideshow, printing or sharing
- No animated GIF/WebP playback (shows the first frame)
- No AVIF, HEIC or camera RAW support
- No ICC colour management (images are shown as decoded sRGB)
- Windows only

## Install

Build it yourself (requires the [Rust toolchain](https://rustup.rs)):

```
cargo build --release
```

The result is `target\release\winpicview.exe`. To make it your default viewer:

```
winpicview.exe --install
```

This copies the exe to `%LOCALAPPDATA%\Programs\WinPicView`, registers the file types for your user, and opens **Settings → Default apps** on WinPicView's page. Windows does not allow programs to set themselves as the default, so you choose WinPicView there once per file type (or use *Open with → Always* in Explorer). `--register` registers the exe where it currently is, and `--unregister` removes everything it added.

## Opening-speed comparison

For curiosity: how quickly does each viewer put a picture on screen from a cold start? Photos was compared at the same version on the same machine.

| | |
|---|---|
| Machine | AMD Ryzen 5 4600H, 16 GB RAM, Windows 11 Pro (build 26300) |
| WinPicView | 0.1.0, release build |
| Microsoft Photos | 2026.11090.22001.0 |
| Runs | 12 per app per image, process killed between runs |

Test images are small JPEG thumbnails (the three below are representative of a folder of 18).

| Test image | Resolution | File size | WinPicView (median) | Photos (median) | Speed-up |
|---|---|---|---|---|---|
| A | 256 × 384 | 20 KB | **99 ms** | 1,035 ms | ~10× |
| B | 384 × 256 | 20.4 KB | **96 ms** | 1,109 ms | ~12× |
| C | 1024 × 682 | 74.4 KB | **99 ms** | 1,118 ms | ~11× |

Min–max across runs: WinPicView 93–166 ms, Photos 991–1,213 ms.

**How it was measured:** a PowerShell script starts a stopwatch, launches the viewer on the file (WinPicView by running the exe, Photos through its `ms-photos:` protocol), and polls until the viewer's window is visible and its title shows the file name. Timing includes process start-up. Polling resolution is a few milliseconds.

**Caveats:** this measures *cold-start to first image shown* on one machine, using small files, so it mostly reflects start-up cost rather than decode speed for large photos. Photos does considerably more (library, cloud and editing features) and may behave differently when already running in the background or on other hardware. Treat the numbers as an illustration, not a rigorous benchmark.

## How it works

- `image` crate decodes files; a mip-map chain is built for each picture so zoomed-out views stay sharp and fast
- A multithreaded CPU sampler (bilinear when zoomed out, nearest-neighbour when zoomed in past 300%) renders into a `softbuffer` surface in a `winit` window
- Neighbouring images are decoded on background threads and kept in a small byte-capped cache
- Text overlays use the system Segoe UI font via `fontdue`
- File associations are written to `HKCU` only
